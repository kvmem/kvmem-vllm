吞吐和状态如何计算

Prefill：原生 prompt 计数减去缓存 token，再对相邻采样做差分。已恢复的历史不计为新增计算；这是混合工作负载下的速率，不是独立 prefill 压测。

Decode：原生实际输出 token 的增量除以墙钟时间，包含首 token，排除未接受的推测 token。不是单路生成速度，也不是纯 decode 窗口。

运行请求：原生引擎 running 指标，可能包含 prefill、decode 或准备中的请求，不等于同时 decode 的数量。“模型请求中”含排队和恢复；“工具／客户端”表示该 agent 当前没有在途模型请求。

CPU：容量内已预留空间包含本轮输出和推进余量，可准入余量不等于物理空闲内存。完成评分后才计入通过率，基础设施异常单独统计。

整轮输出吞吐：已完成模型请求的接受输出 ÷ 正式开始以来的墙钟时间，包含工具、评分、恢复与等待；尚未完成请求的输出会在请求结束后补入。工具报错率：去重后的 is_error 工具结果占比，不等同于非零 shell 退出码或隐藏测试失败率。
