# 当前 KVMem / 原生 vLLM 的真实 DeepSWE 容量与吞吐对照

2026-10-27 启动。结果以产物中的实际完成记录为准；本文不预设加速。

## 已确认的评估重点：长历史 8 并发

用户确认关注的是 8 个真实长历史请求同时进入系统时的 QPS 和吞吐。
报告以已完成的约 229K 历史对照为主结果，短窗口 agent 测量作为补充。
这里的 8 并发是同时提交 8 个请求；原生引擎自行排队、抢占和重算，
这些成本全部计入时间。共同上下文上限为 256K，实际历史不填充。

8 份真实历史各续接固定 4,096 输出 token，实测：

| 指标 | 关闭 KVMem | 开启 KVMem |
| --- | ---: | ---: |
| 整批续接时间 | 550.81 秒 | 75.71 秒 |
| 续接 QPS | 0.01452 | 0.10567 |
| 续接输出吞吐 | 59.49 token/s | 432.81 token/s |
| 续接抢占 | 5 次 | 0 次 |

本组续接 QPS / 吞吐达到原生的 7.28 倍，含首次准备的整批吞吐为 2.30 倍。
每个后端已完成一轮固定工作量测量；这些数值不作为长期稳态或绝对最大 QPS。
完整数据和容量证据见 `artifacts/deepswe-qps-256k-20261027-r2/report.md`。

## 原冻结设计与运行记录

- 单卡 RTX PRO 6000 Blackwell Server Edition，97,887 MiB；同一份本地
  Qwen3.8-27B NVFP4 权重、FP8 KV、MTP4、CUDA Graph，vLLM 0.30.0。
- 相同最大逻辑上下文 262,144 token、单轮最多 16,384 输出 token，
  GPU memory utilization 0.72、max_num_seqs 8、有效 batch 16,424、普通
  prefill chunk 2,048；不人为限制原生引擎的长请求准入。
- KVMem 使用当前源码快照的 K=98,304 / G=16,384、MeanK/FPS4 各半、
  100 GB CPU 历史预算、现有驻留/恢复优化。关闭历史 LRU 删除，保留上限内
  完整 CPU KV。由于无 GC 的 FPS 配置要求图容器，使用 multi/alpha=0；
  alpha=0 不引入图分数。
- 对照直接启动原生 vLLM，禁用 KVMem 插件及环境变量，使用原生异步调度、
  continuous batching 和 prefix cache。这是部署系统对比，包含选择性
  attention 的影响，不称为“只做无损 CPU offload”的加速。
- 固定原始 16 道 DeepSWE 任务、仓库、agent/verifier 镜像、任务顺序及工具，
  全新容器执行真实工具，不用随机文本替代。相同 Claude Code 客户端采用已验证
  的 JSON 字符串保真修复。温度 0.6、top_p 0.95、top_k 20、thinking 4096。
- 并发 1/2/4/8，两个独立配对重复，种子 1000/1001；每组正式窗口 300 秒。
  先测 4/8 再测 1/2，各配对的后端顺序交替，第二轮反转。
- 两边用相同真实历史的 100,352-token 前缀做初始化，独立 cache salt，
  加载/编译/预热/释放不计入正式窗口。该前缀只作初始化，不是任务评分。
- 窗口到期保存未完成容器文件系统和完整轨迹；自然完成任务使用官方隐藏
  verifier，未完成任务不打零分。超出共同上下文上限单独记录，不截断或压缩。

## 指标

| 指标 | 定义 |
| --- | --- |
| QPS | 窗口内成功完成的模型回合 / 窗口墙钟秒；不是完整题目/s |
| 接受输出吞吐 | 原生 generation counter 增量 / 墙钟秒；包含窗口末未完成请求的已生成输出 |
| 交付输出吞吐 | 窗口内完成回合的输出 token / 墙钟秒 |
| 输入计算吞吐 | 实际 local compute prefill token 增量 / 墙钟秒；不重复计入缓存恢复 |
| 延迟 | 完成请求 TTFT、排队和端到端时间 p50/p95；同时报告窗口末未完成请求数 |
| 容量证据 | GPU 页池/占用、抢占、实际 GPU decode batch、CPU 完整历史字节、上下文分布 |
| 任务效果 | 已完成任务的官方评分、上下文上限、窗口截断、工具错误、接口故障分开列示 |

两次重复分别报告后端比值和原始值，不用小样本构造虚假的置信区间。
闭环 agent 的最高观测 QPS 只代表测试并发范围，不能称为给定延迟 SLO 下的
开放到达流最大可持续 QPS。短窗口实际历史可能远小于 256K，应结合长历史
受控续接实验解释，不能将“支持 256K”写成“所有请求都是 256K”。

## 同输入长历史实验

现存真实轨迹导出有 8 份互不相同的完整请求，约 228,827–230,102 token，
来自 4 道实际任务各 2 个回合。两组提供相同完整 token IDs、相同 continuation
token 和独立会话盐；先冷准备、再同时续接固定输出。冷准备和续接分别计时。
不填充到 256K，不将固定输出或 ignore_eos 解释为任务解题质量。
该实验必须实际完成后才报告数字，不能复用 10 月 17 日结果冒充当前版本。

## 实测结果（2026-10-28 完成）

16 个真实任务窗口全部完成，接口错误、上下文超限和抢占均为 0。
短窗口实际展开的是题池前 8 道题；低并发只展开相应数量的前序题。
所有题目都在窗口末截断并保存，没有官方解题评分。

| 并发 | 原生 QPS | KVMem QPS | QPS 变化 | 原生输出 token/s | KVMem 输出 token/s | 吞吐变化 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 0.1115 | 0.1131 | +1.43% | 137.19 | 124.71 | -9.10% |
| 2 | 0.2264 | 0.1680 | -25.79% | 192.13 | 190.78 | -0.70% |
| 4 | 0.3163 | 0.3910 | +23.62% | 278.61 | 316.09 | +13.45% |
| 8 | 0.5871 | 0.6021 | +2.56% | 208.00 | 287.69 | +38.32% |

表中按两个重复的总计数 / 总墙钟汇总。8 并发两次 QPS 变化分别为
+11.50% 和 -5.29%，不能据此声称稳定的 QPS 提升。真实 agent 的回复长度、
工具调用和轨迹会变化，token 吞吐与完成回合数必须分开解释。
本轮实际平均输入约 39K–60K，最长 142,165 token，未使原生组发生抢占。

相同长历史输入对照使用 8 个请求，输入 228,827–230,102 token，
每请求固定生成 4,096 token，全部响应和计数核对通过：

| 后端 | 首次准备秒 | 续接秒 | 续接 QPS | 续接输出 token/s | 含首次准备输出 token/s |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原生 | 647.86 | 550.81 | 0.01452 | 59.49 | 27.34 |
| KVMem | 444.66 | 75.71 | 0.10567 | 432.81 | 62.97 |

续接 QPS / 吞吐为原生的 **7.28 倍（+627.52%）**；含首次准备的整批
吞吐为 **2.30 倍（+130.28%）**。这是固定工作量的真实轨迹回放，
不是在线任务解题速度的倍数，也不代表绝对最大可持续 QPS。

- 原生首次准备抢占 3 次、续接抢占 5 次；KVMem 两阶段均为 0。
- 续接原生 public local-compute prefill 计数为 926,709 token，KVMem 为 8；
  KVMem 私有查询重放不在该计数内，但其耗时及 CPU 传输均计入墙钟。
- KVMem 8 份完整 CPU 历史共 63,935,545,344 字节，KV 磁盘读写均为 0。
- 续接中记录到 798 个纯 8 路解码步；这些步中最小逻辑历史为 228,833 token，
  最大 GPU 活跃长度为 114,656 token。收益同时包含历史保留、选择性 attention
  和减少重算，不能归因于单独的无损 offload。

`artifacts/deepswe-qps-256k-20261027-r2/report.md`。

原生 vLLM Python 文件均未变化；配对输入及所有固定输出配额一致。
